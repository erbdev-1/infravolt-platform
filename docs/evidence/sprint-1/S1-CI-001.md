## Workflow contract

[`ci.yml`](../../../.github/workflows/ci.yml) runs for pull requests targeting `main` and pushes to `main`. It does not use `pull_request_target`, deployments, production credentials or provider access.

- Workflow permissions are explicitly limited to `contents: read`.
- Concurrency cancels only an older run for the same workflow/ref.
- All jobs use `ubuntu-24.04`, Node `24.18.0`, pnpm `11.13.0`, frozen installs, bounded timeouts and immutable action commit SHAs.
- `actions/setup-node` owns the pnpm cache, keyed through `pnpm-lock.yaml`; no build output or credential-bearing state is cached.
- `quality` performs runtime, workflow, dependency, audit, credential, environment, server-boundary, common-contract, market, feature, safe-state, local-Docker-boundary, typecheck, lint, Vitest and production-build gates.
- `browser-smoke` starts only after `quality`, installs the pinned local Playwright Chromium, verifies the controlled failure-artifact contract and runs the UK, UA and unknown-host projects.
- `database` starts only after `quality`, pins `DOCKER_HOST` to the local Unix socket, runs the deterministic WP-11 foundation and always invokes the bounded local cleanup step.

## Artifact and secret-safety controls

- Playwright uploads occur only on failure and include only bounded ZIP traces, PNG screenshots and JSON diagnostics under the WP-15 artifact directory.
- Artifact retention is three days; missing artifacts do not hide the original failed check.
- Raw logs, environment dumps, videos and unrestricted repository output are not uploaded.
- Pull-request code receives no repository or provider secret.
- Credential errors report pattern class/path or commit identifier only; matched values are never emitted.
- The quality checkout uses full history with persisted checkout credentials disabled so FND-025 cannot silently degrade to a shallow worktree-only scan.
- A real credential finding remains an incident requiring rotation; removing a file alone is not represented as remediation. The operational rotation runbook remains owned by WP-16/IAM-027.

## Dependency-security remediation

The initial fail-closed audit reported eight high and six moderate advisories through Next.js, Sharp/libvips, PostCSS and `brace-expansion`. The dedicated remediation commit is `8f1e879`.

| `next > postcss` | `8.4.31` | exact parent-scoped override to `8.5.18` | patched PostCSS path |

`eslint-config-next` moved from `16.2.10` to the matching `16.2.11`. The three Next-owned plugins execute correctly on ESLint 10 but have stale peer declarations, so `pnpm-workspace.yaml` permits only those exact plugin/version to ESLint `10.8.0` combinations. `pnpm peers check` reports no issue; there is no global peer ignore.

The initial ESLint 10 run reproduced a `react/display-name` legacy rule-context failure. Exact `@eslint/compat@2.1.0` and `fixupConfigRules` provide the official minimal compatibility layer without disabling rules. A temporary ignored negative TSX fixture then produced exit `1` for active Next.js, React, React Hooks, TypeScript, import and accessibility rules and was removed unconditionally. The clean repository lint exits `0`.

Final `pnpm audit --audit-level high` exits `0` with no known critical, high, moderate or low vulnerability reported. Direct packages remain exact; only `sharp@0.35.0` and the pre-existing `unrs-resolver@1.12.2` may run reviewed build scripts.
